Know what is inside any app, installer or file.

A finding describes that one file and says how sure it is. It is not a verdict on the project: “low” and “medium” order the reading, and many such findings are ordinary choices of a build. The files were only read, never run.

A report you can check

It does not ask you to trust it. Each finding says how sure it is and points at the bytes it came from.

An illustration of how a finding reads. The names and numbers are made up.

  • Evidence for everything. File, position and the value that was read. In the desktop app, one click shows the bytes.
  • Honest about confidence. Verified, derived or heuristic. A heuristic says it may be wrong.
  • Says what it could not do. Encrypted, unreadable or over a limit: it is listed, never passed over in silence.
  • No verdict. It does not call anything safe or unsafe. It shows you what is there.
  • Seven formats. HTML, PDF, Markdown, plain text, JSON, SARIF and CycloneDX.

How it works

One pass, read only. Every output format is written from the same report, so they always agree.

1

Input

Any file or folder. It is only read, never run or installed.

→
2

Unpack

Containers are opened layer by layer, within fixed limits.

→
3

Analyze

Each file goes to the analyzers that understand it: content, binary, Apple, Android, Windows.

→
4

Correlate

Files are related to one another: what signs what, what contains what.

→
5

Report

Findings with evidence and confidence, plus what could not be read. Seven formats.

↑ the same engine, reached three ways ↑
Command lineRuns the engine directly.
Desktop appA window, and a separate worker process that does the analysis and can always be stopped.
AI, optionalReads the finished report through read-only tools; never the files.

What it reads

Containers are opened layer by layer, so an app inside a disk image inside a zip is still found.

Apple.app, IPA, DMG, pkg · code signatures and certificate chains, entitlements, provisioning profiles, privacy manifests, FairPlay encryption
AndroidAPK, AAB, XAPK / APKS · manifest, resources, signature schemes v1–v3.1, DEX, SDKs and packers
WindowsPE, MSI, NSIS, Inno Setup, CAB, MSIX, Electron, .NET · Authenticode, installed program folders
AnythingMach-O, ELF and PE hardening · zip, tar, 7z and more, nested · URLs, likely credentials, entropy, duplicate files

Two ways to use it

The same engine underneath: one input gives the same report in both.

>_

Command line

For scripts and CI. Compare two versions with diff, fail a build with --fail-on high.

▣

Desktop app

For macOS. Drop a file, read the report, click evidence to see its bytes, keep a history.

◎

For AI agents

A read-only MCP server lets an agent look things up in a report.

Optional · off by default

Let an AI walk you through the report

Add --ai and a model explains the report in plain words. It sees the report, never your files. Every statement must cite findings of the report; those that do not are dropped.

Install

Released for Macs with Apple silicon. On other systems, build the command line from source.

# the command line
$ brew install atomsprout/tap/analyze-anything

# the desktop app
$ brew install --cask atomsprout/tap/analyze-anything-desktop

# then
$ analyze-anything <file or folder>
# from source, with Rust 1.90 or newer
$ git clone https://github.com/atomsprout/analyze-anything
$ cd analyze-anything && cargo build --release
