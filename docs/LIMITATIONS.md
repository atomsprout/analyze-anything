# 已知局限

这里列的是工具本身做不到或没有验证过的事。单次分析中遇到的具体问题会写在那份报告的“覆盖度与局限”一章。

## 设计上不做

- 不执行、不安装、不动态调试被分析的对象。
- 不反编译成伪代码。
- 不解密、不脱壳、不绕过任何保护。App Store 下载的 IPA 主程序被 FairPlay 加密，代码段读不了；加固过的 APK 真实代码不可见。这些情况会被识别并写进报告。
- 不联网。因此不检查证书吊销、根证书是否受信任、Apple 公证状态。
- 不给出“安全 / 不安全”的结论或单一评分，只列出结论和它们的严重度。

## 没有真实样本验证过的部分

以下功能只用自己构造的数据测试过，没有在真实样本上对照过参考工具：

- **Apple**：ADC 压缩的 DMG 块、以压缩方式存储的文件、APFS 快照和多卷、pbzx 格式的 pkg、ECDSA 签名。加密的 DMG 只能识别，不能读取。
- **Windows**：Inno Setup 6.4 能解出文件，但参考工具读不了这个版本，结果无法核对；NSIS 1.x / 2.x 和分支版本未测试；MSI 自身的数字签名只记录有没有，不校验；RAR 自解压只导出附加数据，不解包（许可证原因）；Quantum 压缩的 CAB、多卷和外部 CAB 不解包。
- **Android**：XAPK / APKS 只用手工构造的样本测试过；加固壳、Janus、非常规压缩方式只在构造的样本上测试过；AAB 只深入分析 base 模块；文本格式的清单（apktool 的输出）不解码。
- **二进制**：Mach-O 的导入导出只读符号表，不解析导出字典树和链式修正；PE 的延迟导入只在自己构造的样本上验证过。

## 真实样本只在 Linux 上分析过

自动测试在 Linux、macOS、Windows 上都通过了（GitHub Actions）。但用真实样本做的分析和与参考工具的对照，都是在 Linux 上进行的。

## 没有与平台自带工具对照过

Apple 签名的对照用的是 `rcodesign`，Windows 签名用的是 `osslsigncode`。没有在真实的 macOS 上用 `codesign`、在真实的 Windows 上用 `signtool` / `sigcheck` 对照过。

## 其他

- PDF 内嵌的字体只覆盖中文和拉丁字符，其他文字（韩文、阿拉伯文、表情符号等）在 PDF 里显示为方块，除非用 `--font` 追加字体；HTML 和 JSON 不受影响。
- 没有每分析器的超时：单个分析器卡住会让整次运行卡住。崩溃会被隔离并记为局限。
- 带 PDF 的可执行文件约 49 MB，其中中文字体 8.6 MB。
- 启发式结论（疑似凭据、加壳、SDK 识别）可能误报，报告里都标为“启发式”。
- 进程被强行终止时，临时目录里解包出的文件不会被清理（正常结束和出错都会清理）。
