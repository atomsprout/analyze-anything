# Analyze Anything — 第二阶段规划：桌面版

> 版本：规划稿 v0.1（2026-11-19）。前置：第一阶段的命令行工具已完成，见 [PLAN.md](PLAN.md)。
> 一句话定位：**同一套分析引擎的图形界面。拖入文件 → 看进度 → 浏览报告 → 导出。** 不新增分析能力。

---

## 0. 摘要

| 事项 | 决定 |
|---|---|
| 框架 | Tauri 2（当前稳定版 2.12，需要 Rust 1.90，我们固定在 1.100） |
| 平台顺序 | 先 macOS；Windows 和 Linux 在 macOS 版可用后再做 |
| 报告界面 | 复用第一阶段的 `report.html`，不重写 |
| 分析在哪里跑 | 独立的子进程，不在界面进程里（见 §3.2） |
| 前端 | TypeScript + Vite，不引入界面框架（见 §3.4，待确认） |

**macOS 版估时约 8–10 周**，分 6 个里程碑（§6）。这是粗估，D0 的技术验证做完后再修正。

**开工前需要你确认的事**在 §9。

## 1. 产品定义

### 1.1 做什么

1. **打开**：把文件或文件夹拖进窗口，或用"打开"对话框选择。
2. **分析**：显示阶段和进度（正在读哪个文件、解开了几个容器），可以取消。
3. **读报告**：概览、需要关注、12 个章节、文件清单、覆盖度与局限；可筛选、搜索、切换中英文。
4. **看证据**：点击一条结论，跳到它引用的文件和位置；对字节范围显示十六进制视图。
5. **浏览文件树**：解包后的完整产物树，每个文件的类型、大小、哈希、分析器读出的数据。
6. **导出**：PDF、HTML、Markdown、TXT、JSON、SARIF、CycloneDX，以及带清单的输出文件夹。
7. **历史**：以前分析过的报告列表，可以重新打开。
8. **对比**：选两份报告，看新增、消失、变化的结论（典型用途：同一个应用的两个版本）。

### 1.2 不做什么

- 不新增任何分析能力。命令行能看到的，桌面版才能看到；反过来也一样。
- 不执行、不安装被分析的对象，和命令行一致。
- 不联网。没有账号、没有云同步、没有遥测。
- 第二阶段不做：自动更新、插件系统、AI 解读（属于第三阶段）。

### 1.3 与命令行的关系

桌面版和 `aa` 共用 `aa-engine`、`aa-report`、`aa-export`。同一个输入在两边得到字节相同的 `report.json`，这一点要有自动测试保证。

## 2. 现状：引擎离桌面版还差什么

第一阶段规划的 §3.4 列了七条"为桌面版预留"的约束。逐条核对实际代码：

| 约束 | 现状 |
|---|---|
| 分析逻辑全在库里，CLI 是薄壳 | 已满足 |
| 统一入口 `analyze(input, options, sink)` | 已满足 |
| 进度是结构化事件 | **部分满足**：建树阶段有逐文件事件；分析阶段只有一个"开始分析"事件，没有逐文件进度；事件类型还不能序列化 |
| 可取消 | 已满足 |
| `report.json` 自包含 | 已满足，`aa render` 证明了这一点 |
| 按节点取字节 | **未满足**：分析结束后产物树就被丢弃，解包出的文件随之消失，没有对外读取接口 |
| 配置是数据 | 已满足 |

所以桌面版开工前，引擎要先补两件事（放在 D1）：

1. **分析会话**：新增一个返回"报告 + 仍然可读的产物树"的入口，会话存活期间可以按路径读任意文件的任意字节范围；会话结束时清理临时文件。
2. **进度事件**：分析阶段按文件报告进度；事件类型支持序列化，便于跨进程传递。

## 3. 架构

### 3.1 目录

```
analyze-anything/
├── crates/                  # 第一阶段的 12 个 crate，不动结构
│   └── aa-engine            # 补：分析会话、可序列化的进度事件
├── apps/
│   └── desktop/
│       ├── src-tauri/       # Rust：窗口、命令、子进程管理、历史记录
│       └── src/             # 前端：TypeScript
└── docs/
```

`apps/desktop/src-tauri` 是工作区的一个新成员。它不进入 `aa` 命令行的依赖，命令行的体积和构建时间不受影响。

### 3.2 分析放在子进程里

界面进程不直接调用引擎，而是启动一个工作子进程来分析，两者通过标准输入输出传 JSON 消息。

这样做的理由：

- **卡死能真正终止**。第一阶段的超时只能"放弃等待"，卡住的线程杀不掉。换成进程就可以直接结束它。
- **崩溃不带走界面**。引擎已经隔离了 panic，但栈溢出、内存耗尽这类问题隔离不了。
- **内存用完即还**。分析大文件占的内存在子进程退出时全部归还。
- **取消是确定的**。先发取消消息，几秒内不退出就强制结束。

工作子进程就是桌面程序自己带一个隐藏参数再启动一次，不需要额外分发一个可执行文件。

代价是多一层消息协议，以及"读证据字节"要走进程间通信。读字节的请求量小（用户点一下才读一次），可以接受。

### 3.3 消息协议

界面进程 → 工作进程：`analyze`、`cancel`、`read_bytes`、`close`。
工作进程 → 界面进程：`progress`（逐文件）、`report`（完成）、`bytes`、`error`。

每条消息一行 JSON。协议写成 Rust 类型，放在一个小 crate 里，两边共用；有往返测试。

### 3.4 前端

- **语言和构建**：TypeScript + Vite。
- **不引入界面框架**（React、Vue、Svelte 都不用）。理由：外壳界面只有四个视图（主页、进度、报告、对比），现有的报告界面是 51 KB 的原生脚本，再引入一个框架会让两套写法并存。这一条待你确认（§9）。
- **报告视图**：把 `aa-report` 渲染出的 `report.html` 放进一个受限的内嵌框架里显示，通过自定义协议（如 `report://<id>/`）加载，不写临时文件。
- **报告界面的改动**：现有 `app.js` 增加一个"宿主模式"：在桌面版里，点击证据时把"文件路径 + 字节范围"通过消息发给外壳，由外壳打开十六进制视图。单独打开的 `report.html` 行为不变。
- **十六进制视图**：新写。按需向工作进程要字节，虚拟滚动，不一次读入整个文件。

### 3.5 历史记录

- 存在系统的应用数据目录下，每次分析一个文件夹：`report.json`、`manifest.json`、少量元数据（输入名称、时间、输入的 SHA-256）。
- **不保存被分析的原始文件**，也不保存解包出的内容。重新打开历史报告时能读报告，但看不了十六进制证据，界面要说明原因，并提供"重新分析"。
- 分析时间只记在历史索引里，不进 `report.json`，报告仍然可复现。
- 提供"删除这条"和"清空历史"。

### 3.6 对比

- 结论的 ID 是内容的哈希，同一个观察在两份报告里 ID 相同。对比先按 ID 找出完全相同的结论，剩下的按"规则 + 文件路径"配对，配上的算"变化"，配不上的算"新增"或"消失"。
- 对比逻辑放在库里（`aa-export` 或一个新 crate），命令行同时得到 `aa diff a.json b.json`。
- 文件层面同理：按路径和哈希，列出新增、删除、内容变化的文件。

## 4. 安全

桌面版多了一个攻击面：报告里的文字来自不可信的文件，现在要在一个有权限的应用里显示。

- **内容安全策略**：沿用报告页已有的严格策略（只允许带哈希的内联脚本和样式，禁止一切外部加载）。外壳页面同样禁止远程内容。
- **报告框架受限**：内嵌框架开启沙箱，不能访问外壳的接口；它和外壳之间只有一种消息（"打开这个证据"），外壳收到后校验路径确实属于当前报告。
- **最小权限**：Tauri 的权限清单只开放需要的命令。不开放执行外部程序的能力；文件读写只限用户通过对话框或拖放选择的路径，以及应用数据目录。
- **拖入的路径**：只读，不跟随符号链接，和命令行一致。
- **工作进程**：崩溃或被杀掉后，界面进程负责清理它留下的临时目录。

## 5. 测试

| 层 | 方法 |
|---|---|
| 引擎的分析会话、读字节 | Rust 单元测试和集成测试；读出的字节与原文件、与 7-Zip 解出的内容比对 |
| 消息协议 | 往返测试；畸形消息不让任何一方崩溃 |
| 工作进程 | 启动真实子进程：正常完成、取消、超时强杀、崩溃后清理 |
| 与命令行一致 | 同一输入，桌面版和 `aa` 的 `report.json` 逐字节相同 |
| 前端逻辑 | 单元测试（Vitest） |
| 报告界面的宿主模式 | 沿用现有的 Playwright 浏览器测试，加上"点击证据发出正确消息" |
| 对比 | 构造成对的报告，验证新增、消失、变化的分类 |
| 整个应用的端到端 | 见下 |

**端到端测试的限制**：Tauri 官方的自动化驱动只支持 Windows 和 Linux，macOS 的系统 WebView 没有对应的驱动。所以：

- 自动化的端到端测试在 Linux 的 CI 上跑。
- macOS 上，界面用浏览器测试覆盖（后端用模拟数据），Rust 侧用上面的各层测试覆盖，整机流程靠一份手工检查清单。
- 这意味着 macOS 版的"拖入 → 报告 → 导出"全流程没有自动化保障，需要你在真机上验收。

## 6. 里程碑（macOS 优先）

每个里程碑结束时都有一个能运行的应用。

| 里程碑 | 内容 | 验收 | 估时 |
|---|---|---|---|
| **D0 技术验证** | 最小 Tauri 应用；子进程 + 消息协议跑通一次分析；自定义协议加载 `report.html`；确认严格的内容安全策略在 WebView 里生效；量一下应用体积和启动时间 | 能拖入一个文件并看到报告；写一份验证结论 | 1 周 |
| **D1 引擎补齐** | 分析会话（保留产物树、按范围读字节）、逐文件进度、事件可序列化、消息协议 crate | 测试通过；命令行行为和输出不变 | 1–1.5 周 |
| **D2 主流程** | 拖放和打开、进度界面、取消、报告视图、中英切换、导出各格式 | 完整走通"打开 → 分析 → 读 → 导出"；与命令行输出逐字节一致 | 2 周 |
| **D3 证据与文件树** | 报告界面的宿主模式、十六进制视图、文件树浏览、从结论跳到证据 | 点任意一条带字节范围的结论能看到对应字节 | 1.5–2 周 |
| **D4 历史与对比** | 历史列表、重新打开、删除；对比逻辑和界面；`aa diff` | 同一应用的两个版本能看出新增和消失的结论 | 1.5 周 |
| **D5 打包与打磨** | `.app` 和 DMG、图标、菜单、快捷键、深浅色、错误提示、CI 构建；签名和公证（取决于 §9 的答复） | 一个可以分发给别人安装的 macOS 版 | 1–1.5 周 |
| **D6 Windows 与 Linux** | 构建、安装包（MSI / NSIS、AppImage / deb）、平台差异、Linux 上的端到端测试 | 另行估时，约 1–2 周 | 之后 |

## 7. 风险

| 风险 | 对策 |
|---|---|
| 严格的内容安全策略与 Tauri 注入的脚本冲突 | D0 验证；报告放在独立的受限框架里，本来就不需要 Tauri 的接口 |
| macOS 没有端到端自动化 | 把逻辑尽量压到可测试的层；手工检查清单；Linux 上跑自动化 |
| 没有 Apple 开发者证书时，别人打开应用会被系统拦截 | 见 §9；没有证书也能自己用，只是分发受限 |
| 体积：引擎带 PDF 约 48 MB，加上外壳 | D0 实测；必要时桌面版把 PDF 做成可选 |
| 大报告（几万个文件）在界面里卡顿 | 现有报告界面已用虚拟滚动测过 5 万个文件；十六进制视图同样按需加载 |
| 历史记录里的报告与新版本不兼容 | `report.json` 有版本号；读到旧版本时提示重新分析 |
| 第一阶段没做完的实测反馈会改动报告界面 | 报告界面只有一份，改动自动带到桌面版 |

## 8. 对第一阶段的影响

- `aa-engine` 增加分析会话和更细的进度事件；现有入口保留，命令行的行为和输出不变。
- `aa-report` 的报告脚本增加宿主模式；单独打开的 `report.html` 不变。
- 新增 `aa diff` 命令。
- 命令行可以选择复用子进程方案，让 `--analyzer-timeout` 真正终止卡住的分析。这是可选项，不在本阶段承诺。

## 9. 开工前需要确认

1. **Apple 开发者账号**：有没有 Developer ID 证书？有的话 D5 做签名和公证，别人下载后可以直接打开；没有的话应用只能自己用，或让对方手动放行。
2. **前端不用界面框架**：我建议只用 TypeScript。如果你更熟悉 React、Vue 或 Svelte 并打算自己改界面，可以换。
3. **应用名称和标识符**：默认"Analyze Anything"和 `com.atomsprout.analyze-anything`。
4. **历史记录不保存原始文件**：我建议不保存，避免应用数据目录里攒下一堆待分析的样本。代价是历史报告看不了十六进制证据。
5. **自动更新**：我建议第二阶段不做，发布新版时手动下载。
