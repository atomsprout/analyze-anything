# 桌面版技术验证（D0）结论

2026-11-19，Apple 芯片的 Mac，macOS 27.2，Tauri 2.12，系统 WebView（WKWebView）。规划里列为风险、需要 D0 回答的问题，结论如下。

## 能不能拖入一个文件并看到报告

能。最小应用把“自己带 `--worker` 再启动一次”作为工作子进程，两者用每行一个 JSON 的消息通信，跑通了一次真实分析；报告页通过自定义协议 `report://localhost/<id>` 加载进内嵌框架并正常显示。

## 严格的内容安全策略在 WebView 里是否生效

生效，两层都验证过。

- **报告页**：`report.html` 自带的策略（`default-src 'none'`，脚本和样式只按 SHA-256 放行）原样生效，交互界面正常运行。它所在的框架是 `sandbox="allow-scripts"`，没有同源权限，Tauri 的接口不会注入进去，它也调用不到外壳的任何命令。规划里担心的“严格策略与 Tauri 注入的脚本冲突”没有发生：冲突的前提是 Tauri 往这个框架里注入脚本，而它不注入。
- **外壳页**：`default-src 'none'; script-src 'self'; frame-src report:; connect-src ipc: …`。应用自检在真实窗口里确认：动态插入的内联脚本不执行，`eval` 被拒绝，`fetch` 外部地址被拒绝。

一个值得记下的细节：开发服务器（Vite）会改写它提供的 HTML 页面，报告页一经改写，脚本的哈希就对不上，被策略拒绝后整页空白。所以浏览器测试里的样例报告由一个不做任何改写的中间件原样提供。应用里没有这个问题，报告页由 Rust 端直接渲染。

## 跨进程读证据字节够不够快

够。十六进制视图按 64 KB 一块向工作进程要数据，只画屏幕上的行；点一条证据到字节显示出来没有可感知的延迟。字节以十六进制文本过两层进程间通信（工作进程 → 界面进程 → 页面），一块约 128 KB 文本。

## 取消是否确定

是。取消时先发消息，工作进程 5 秒内没有结束就强制结束。对一个 320 MB、解出 7461 个文件的 DMG，在分析进行中点取消，约 1.1 秒回到主页；退出后没有遗留的工作进程和临时文件。用“完全不响应”的假工作进程测试，强制结束在 5 秒宽限后发生。

## 体积

| 项目 | 大小 |
|---|---|
| 命令行 `analyze-anything`（含 PDF） | 45 MB |
| 桌面版可执行文件（含 PDF、WebView 外壳） | 50 MB |
| `Analyze Anything.app` | 48 MB（磁盘占用） |
| DMG | 26 MB |
| 命令行 tar.gz | 24 MB |

外壳只让可执行文件比命令行多了约 5 MB，因为 WebView 用系统自带的。规划里“必要时把 PDF 做成可选”的退路不需要用。

## macOS 上没有端到端自动化怎么办

规划的对策是“手工检查清单”。实际做法更进一步：应用带一个自检模式，在真实窗口里由页面自己点击自己的界面走完全流程并写出结果，外部脚本再把导出的文件与命令行输出逐字节比较（[tools/desktop-check](../../tools/desktop-check/)，说明见 [DESKTOP.md](../DESKTOP.md)）。这样真实 WebView 里的 53 项检查是自动的；只剩原生菜单、拖放、系统对话框三处需要人工看一眼。

页面与报告页的配合（沙箱框架里点击“查看字节”→ 外壳收到消息 → 打开十六进制视图）用 Playwright 在 WebKit 和 Chromium 里测，后端用模拟数据。

## 估时修正

规划估 D0–D5 共 8–10 周。实际上报告界面复用、引擎本来就按“库 + 薄壳”写好，使外壳的工作量远小于估计；最花时间的不是界面，而是让取消、清理、与命令行逐字节一致这几件事可以被测试证明。
